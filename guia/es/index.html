CLI · Cloudflare DNS

Registro DNS en un comando — sin abrir el panel.

Un script de Python en un solo archivo que crea, lista y elimina registros en Cloudflare mediante la API. Incluye el par CNAME + TXT que Vercel solicita para verificar un subdominio nuevo.

Empezar la guía Ver en GitHub
Qué es

Un archivo, cero dependencias

El panel de Cloudflare es excelente para consultar y pésimo para repetir. Este script hace lo mismo mediante la API, de una forma que puedes versionar, revisar y volver a ejecutar mañana.

📦 Solo la biblioteca estándar de Python 3

Nada de pip install. Copia el cf-dns.py para cualquier máquina con Python 3 y funciona — servidor nuevo, contenedor, VPS recién creada.

🔑 Token fuera del código

La credencial viene de la variable CLOUDFLARE_API_TOKEN o de un .env apuntado por CF_ENV_FILE. No hay ningún secreto en el repositorio.

▲ Acceso directo a Vercel

El subcomando vercel crea el CNAME y el TXT de verificación de una vez, con el proxy desactivado desde el inicio — ese es el detalle que suele bloquear la verificación.

Cómo funciona

Tres llamadas a la API, en el orden correcto

No hay magia: el script se comunica con la API v4 de Cloudflare. Lo que agrega es un orden seguro: mirar antes de escribir.

Lee el token→ Descubre el zone_id→ Lista lo que ya existe→ Crear / borrar→ Verificar

Buscar la zona

GET /zones?name=<dominio> devuelve el zone_id. Todo registro depende de ese id: siempre es el primer paso.

Mirar antes de escribir

GET /zones/<id>/dns_records?name=… muestra lo que ya está ahí. Así evitas descubrir un conflicto solo después de que el sitio deje de funcionar.

Escribir

POST crea y DELETE /dns_records/<record_id> elimina. El list imprime el id de cada registro, que es lo que el delete consume.

Requisitos previos

Un token y Python; nada más

No hay ningún servicio que poner en marcha, ni daemon ni base de datos. El script es stateless: cada ejecución es una conversación breve con la API.

Python 3

Cualquier versión 3.x que incluya tu distribución. No se importa ningún paquete externo.

# verificar
python3 --version

API Token de Cloudflare

En el panel: My Profile → API Tokens → Create Token, plantilla Edit zone DNS. Permiso Zone → DNS → Edit en las zonas que vas a modificar. El token aparece una sola vez.

# guardar fuera de git
echo 'CLOUDFLARE_API_TOKEN=SEU_TOKEN' >> ~/.env
chmod 600 ~/.env

El dominio en Cloudflare

La zona ya debe estar en la cuenta y el token debe tener acceso a ella. Si no lo tiene, el script lo indica en lugar de fallar en silencio.

# prueba de humo
./cf-dns.py list inema.club
Guía de uso · paso a paso

Del clon al registro activo

Cinco pasos. El cuarto es el que vas a repetir siempre.

1

Instálalo en una máquina nueva

El repositorio entero es el script más la documentación. Copia el archivo donde tu $PATH alcanza.

git clone https://github.com/inematds/cf-dns
install -m 755 cf-dns/cf-dns.py ~/bin/cf-dns.py
2

Indica el token

Dos formas: variable de entorno o un archivo .env indicado por CF_ENV_FILE. Sin ninguna de las dos, el script se niega y explica el motivo.

# variable de entorno
export CLOUDFLARE_API_TOKEN=seu_token

# o apuntando a un archivo
export CF_ENV_FILE=~/.env
3

Mira antes de modificar

Siempre. El list muestra el tipo, el nombre, el valor, el estado del proxy y el id de cada registro — y así descubres si hay un A ocupando el host que ibas a usar.

./cf-dns.py list inema.club          # toda la zona
./cf-dns.py list inema.club dlp2     # solo un nombre
4

Crea el registro

El nombre puede ser el subdominio puro (rede) o el dominio completo. El TTL predeterminado es de 60 segundos: útil mientras se verifica algo.

# A apuntando a una IP
./cf-dns.py add inema.club A rede 192.168.2.99

# CNAME con TTL más alto
./cf-dns.py add inema.club CNAME app destino.exemplo.com --ttl=300

# con el proxy naranja activado (solo cuando tenga sentido)
./cf-dns.py add inema.club A site 203.0.113.10 --proxied
5

Bórralo cuando lo necesites

O delete usa el id que el list imprimió — no el nombre. Es intencional: tienes que ver el registro antes de eliminarlo.

./cf-dns.py list   inema.club dlp2
./cf-dns.py delete inema.club 76d14e9482f4b03f9d05a3c643f6cca7

Los dos casos que aparecen todas las semanas

Comandos reales, tomados del uso real en los dominios de INEMA.

▲

Subdominio nuevo en Vercel

Vercel pide dos cosas: un CNAME que apunte a vercel-dns y un TXT en _vercel demostrando que el dominio es tuyo. El subcomando vercel hace ambas cosas, ya con proxy desactivado — con el proxy activado, la verificación no pasa.

./cf-dns.py vercel inema.club dlp2 \
  820ed52053a39f8f.vercel-dns-017.com \
  vc-domain-verify=dlp2.inema.club,5bc6ac41fe34ada1f4f9

Varios TXT en _vercel conviven sin problema — uno por subdominio. Cuando Vercel esté en verde, puedes quitar el TXT de ese subdominio.

🏠

Nombre interno para una IP de la LAN

Puedes usar DNS público que apunte a una IP privada: solo se resuelve para quienes están en la red (o en la VPN). El proxy debe estar desactivado: Cloudflare no aplica proxy a direcciones privadas.

./cf-dns.py add inema.club A rede 192.168.2.99
# -> rede.inema.club responde 192.168.2.99 dentro da LAN
